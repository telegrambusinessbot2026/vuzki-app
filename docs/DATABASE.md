# VUZKI - Database Guide

VUZKI uses PostgreSQL via Prisma. The Prisma schema is the single source of
truth for the data model and lives at
`packages/database/prisma/schema.prisma`. The Prisma client is generated by the
`@vuzki/database` package (`prisma generate`) and consumed by the API and
worker.

## Migrations

Migrations are version-controlled SQL files in
`packages/database/prisma/migrations/`. They are the only mechanism used to
change the schema in shared/remote environments - `prisma db push` is
explicitly reserved for local development.

Workflow:

1. Edit `packages/database/prisma/schema.prisma`.
2. Create the migration locally: `npm run db:migrate` (runs
   `prisma migrate dev` in `@vuzki/database`), which produces a timestamped
   migration and applies it to the local DB.
3. Commit the migration alongside the schema change.
4. Deploy: the `migrations` service in
   `infrastructure/docker/docker-compose.yml` runs
   `prisma migrate deploy` against `DATABASE_URL` before API traffic shifts.

Rules:

- Migrations are tested on **staging first**; staging is the validation ground
  before any production schema change.
- Deploy mode is `migrate deploy`, which only applies committed migrations and
  **never auto-drops tables/columns** (`prisma migrate dev` / `db push` reset
  behavior is disallowed against shared databases).
- Destructive changes (dropping columns/tables, renames) must be staged in
  additive migration steps and reviewed; the migration service is one-shot
  (`restart: no`) so a failed deploy fails fast without traffic impact.

## Backup strategy

`scripts/backup.sh` implements the production backup routine:

1. Logical dump with `pg_dump --no-owner --clean --if-exists DATABASE_URL`.
2. Encryption: `age` (preferred) or OpenSSL AES-256-CBC (PBKDF2) with a key
   loaded from `ENCRYPTION_KEY_FILE` (default `/run/secrets/backup_key`).
3. Upload to S3-compatible object storage at `BACKUP_BUCKET/postgres/`
   (default `s3://vuzki-backups`).
4. Retention pruning: backups older than `BACKUP_RETENTION_DAYS` (default 30
   days) are removed from S3 and the local `BACKUP_DIR`.

```bash
BACKUP_BUCKET=s3://vuzki-backups DATABASE_URL=... scripts/backup.sh
```

Restore: `scripts/restore.sh` decrypts the chosen (or most recent) `.age` dump
with the same key file and applies it to `TARGET_DATABASE_URL`, then verifies
the number of restored `public` tables.

```bash
TARGET_DATABASE_URL=... scripts/restore.sh
```

Restore testing: a backup is only considered valid after a restore has been
**tested** - run `scripts/restore.sh` against a disposable/dedicated target
database (never production in place) on a regular cadence to prove the pipeline.

### Point-in-time recovery

Logical dumps capture a single point in time. For finer-grained recovery:

- Enable WAL archiving / continuous archiving on the managed Postgres instance
  (e.g. RDS PITR) so the database can be replayed to an arbitrary timestamp.
- Keep backups in a separately encrypted S3 bucket with versioning and object
  lock, in a different region/account from the primary where required.
- Document and rehearse the RTO/RPO expected by the business; PITR shrinks RPO
  to minutes while logical dumps cover long-horizon recovery and cross-account
  egress.

## Database security

- **Never expose Postgres publicly.** The instance is reachable only on a
  private network/VPC; the docker-compose `5432:5432` host mapping is
  development-only and removed in production. Same for Redis (`6379`).
- **Least-privilege user**: the API connects with a dedicated application user
  (`DATABASE_URL`), not the superuser. It is granted only the schema/table
  permissions the service needs. Migrations run with a separate,
  migration-privileged role.
- **Encryption in transit**: TLS between API/worker and Postgres
  (`sslmode=require` / managed-instance TLS).
- **Encryption at rest**: managed-instance encryption at rest (RDS/EBS or
  provider equivalent).
- **Connection limits**: cap connections per role and rely on the API/worker
  Prisma pool (`connection_limit`) so a connection storm cannot exhaust the DB.
- **Query monitoring**: slow-query logging, `pg_stat_statements`, and anomaly
  alerts on load/latency so runaway queries surface early.
- Backups are encrypted; restore keys and DB credentials live in the secret
  manager, never in the repo.

## Key models overview

Full detail in `packages/database/prisma/schema.prisma`; grouped by domain:

### Auth & users
- `User` - identity, `authProvider` (local/google/apple), username, status
  (ACTIVE/SUSPENDED/BANNED), premium tier, daily streak, referral code,
  `referredById`, soft-delete (`deletedAt`), photo/video selfie verification.
- `Profile` - bio, gender, date of birth, height, location, verification.
- `ProfilePreferences` / `ProfileInterest` / `ProfileLanguage` / `Photo`.
- `Session` - refresh tokens, device/UA/IP, active flag, expiry; `Otp`.

### Matching & discovery
- `Like`, `SuperLike`, `Match`, `Follow` - like/pass/super-like/matching graph
  feeding the discovery feed.

### Chat
- `Conversation`, `Message`, `ReadReceipt` - threaded by `Message.replyToId`,
  reactions, read receipts.

### Calls
- `Call` - status (RINGING/ACTIVE/COMPLETED/FAILED), type (TALK_NOW/PRIVATE),
  started/ended timestamps; `CallParticipant` - role (caller/callee),
  join/leave, RTC join metadata, rating from both sides.

### Wallet, coins & payments
- `Wallet` - coin balance per user; `CoinPackage` - purchasable coin bundles
  (price, coins, bonus); `WalletTransaction` - immutable ledger (type, amount,
  status, `balanceAfter`, metadata).
- `Payment` - provider (razorpay/stripe/cashfree), purpose (COINS/SUBSCRIPTION),
  order/payment id, amount, status, signature (webhook verification).

### Gifts
- `Gift` - catalog (price in coins, animation keys, status);
  `GiftTransaction` - sender/receiver, coins, gift metadata.

### Subscriptions
- `SubscriptionPlan` - tier (FREE/PLUS/PREMIUM/VIP), cycle (monthly/yearly),
  price, features; `Subscription` - user plan, status, renewals/expiry history.

### Creators, earnings & withdrawals
- `CreatorProfile` - application status, hourly rate, rating, KYC status,
  total earnings/minutes; `CreatorApplication`; `CreatorEarning` - per-call/
  gift earnings, status, claimable;
- `Withdrawal` - amount, method, status (PENDING/PROCESSING/COMPLETED/REJECTED),
  payout reference, processor, rejection reason.
- `Referral` - referrer/referred, status (PENDING/ELIGIBLE/PAID), reward coins.

### Safety, moderation & anti-fraud
- `Report` - category, description, status, resolution, reporter/reported;
  `Block`; `ModerationAction`; `ModerationCase`; `Appeal`; `UserRestriction`;
  `BanTemplate` (if present).
- `SafetySignal` - device/IP/behavior signals; `UserRisk` - internal risk
  score, **never exposed publicly**.
- `FraudFlag` - payment/referral/withdrawal/earning/gift fraud flags;
  `ContentFlag` - AI-assisted image/text/voice review queue;
  `ModerationAudit` - AI moderation audit trail (model, version, category,
  confidence, result, decision).
- `SecurityEvent` - suspicious login/device events; `Verification` - badge
  verification requests (MANUAL/KYC/ID_DOC).

### Notifications, boosts, rewards, admin
- `Notification` - per-user, types incl. SYSTEM/referral/earnings; `Boost`;
  `Reward` (daily streak); `Admin`, `AdminRoleModel` (role+permission matrix),
  `AuditLog` - immutable admin action trail.

### Account deletion
- `AccountDeletion` - one deletion job per user (PENDING -> PROCESSED ->
  ANONYMIZED), `retentionUntil`, processed by the worker
  (`apps/api/src/services/deletion.ts`); anonymization removes/irreversibly
  scrubs personal data while retaining required records where mandated.
